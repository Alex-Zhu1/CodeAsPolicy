## 正常路径与复杂情况的约定

1. **从下一步有用动作组织代码。** Astra 选择当前阶段需要定位的对象、动作目标、检查与有限纠偏。
   同一 cell 可以包含多步有依据的操作；只有需要新判断时才交回模型。读取状态和空 cell 不自动算作任务进展。
2. **核验由依赖触发。** 启用 pause 监督时仍须声明 `watch`；自动动作后监督保留。
   显式 `verify` 用于缺失的前置证据、未解决的关键事实或需要核验的决策边界。
   没有额外前置依赖的正常动作，不因为“开始新 cell”就必须再做一次视觉推理。
3. **已有有效快照可直接使用。** 默认 `snapshot()`；需要新的现场证据时才 `refresh=True`。
   历史感知结果仍保留其来源，使用前的当前性检查不被这项优化放松。
4. **模型取得决策信息，宿主保留完整审计。** stdout、几何数值、方法限制、异常、来源引用、
   当前性和未决动作应在受限反馈中优先保留。完整 provenance 与传感器文件可查询，
   无需在每次调用中重复展开。超出输出预算仍需明确省略情况，不能承诺无限输出。
5. **区分操作失败与基础设施失败。** partial/unknown、过期证据和关键依赖继续按原约定阻断或交接。
   已知的采集能力缺失、持续来源或服务错误应归到 host；一次有依据的恢复仍失败时报告具体阻断，
   不让 Astra 重复定位、发送动作或触发操作策略恢复来修理协议。

本轮没有关闭未知动作对账、失效检查、监督或取消确认，也没有引入固定整理桌面脚本。
正常任务策略仍由 Astra 生成，代码执行结束与任务完成仍分别记账。

## 验收顺序与记录要求

| 层次 | 必须观察到的结果 | 不能替代的后续验证 |
| --- | --- | --- |
| 正向与故障回归 | 无额外 requires 的正常动作可继续；确有依赖时先核验；未知动作、旧来源、错配回包仍拒绝 | 替身无法证明真实渲染和机器人链可用 |
| 真实仿真采集/动作 smoke（已通过） | 只读 capture 不增加物理/原生步；公开 API 完成一次小动作；取得精确 native 回执；动作后刷新得到新来源 | 原生动作数大于 0 只证明执行链可用，不是整理任务进展或成功 |
| Astra 完整任务复跑（已完成，任务失败） | 790 原生步、93 高层动作、96 个对齐快照；原生 score=50、success=false，恢复轮次用完后终止 | 完整运行证明链路可用，不证明任务成功、视觉准确率或性能提升 |
| L0/L1 重复对照（后续） | 记录首个有用动作、首次/续轮代码等待、感知/核验执行、返工、完整任务总时长与权威成功判定 | 更早失败、少做动作或只诊断不能算提速 |

smoke 仅用公开状态、图像与动作接口；若视觉客户端使用替身，必须标明只验证执行/传输，
不能宣称真实视觉核验通过。完整任务保留模型终局与原生判定，即使任务失败也保留全部计时和故障记录。

恢复正常能力后，先在当前正确性修复上建立精简控制样本，对照监督、反馈和上下文的收益。
本轮同时修复采集、反馈和提示词，属于功能修复，不能用其前后耗时推断某一个优化因素的贡献。

下一步需核对实际抓取/接近误差、held 的可观测性，以及有用的证据获取方式与调整策略。
unknown 不能单独证明验证器误判，也不能用直接降低阈值或推理投入修复这些质量问题。

这是一轮功能修复后的完整运行，和此前零动作诊断轨迹不是性能 A/B，也不能将等待全部归为模型推理。
