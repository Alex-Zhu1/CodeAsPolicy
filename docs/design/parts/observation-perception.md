# 观测与感知

## 状态与范围

初版依据 2026-10-31 UTC 静态分析；2026-11-01 更新来源协议与只读采集实现，见[闭环实施记录](../interaction-contracts.md)。
“现有实现”描述已读到的代码；“待补齐契约”是目标设计，不代表接口已经可用。
本文覆盖 Robot Use 的状态、图像、标定、几何感知及其来源管理。
`ObservationSnapshot`、`EvidenceRecord`、`CapabilityManifest`、`ActionReceipt`、`BudgetSnapshot`、`HandoffReport` 均为协议草案名称。

## 职责与边界

观测系统负责提供可追溯的现场快照，说明各来源在什么时刻、什么坐标与标定条件下产生。
感知系统负责从指定快照提取区域、位置、几何和不确定性，并保留输入来源。
两者都不据此直接宣布动作完成、物体关系成立或任务完成；事实判定与依赖门控见[验证与证据](verification-evidence.md)。

- 读取历史记录、获取新观测和对已有图像推理是不同能力，必须分别声明。
- 获取观测可以消耗传感器、时间和推理预算；不能隐含机械臂、夹爪或相机机构运动。
- 后端若必须推进仿真才能刷新观测，应明确声明副作用与消耗，不能将它伪装成物理只读采集。
- 改变视角需要动作时，应交由执行系统处理，完成后再获取观测。
- 调用返回的“最新记录”不等于真实环境的“当前现场”。

## 输入与输出

| 能力 | 输入 | 输出 | 主要使用方 |
| --- | --- | --- | --- |
| 历史读取 | 会话、录制索引、相机或状态类型 | 原记录及原来源引用 | Astra、程序、离线评估 |
| 新观测 | 所需来源、时间要求、能力范围、`BudgetSnapshot` | `ObservationSnapshot` 或明确的不可用结果 | 程序、验证器 |
| 几何感知 | 快照引用、目标描述或像素、标定引用 | 区域、坐标、估计方法、限制、来源引用 | 程序、Astra |
| 有效性检查 | 快照、拟使用的能力、现场版本 | 可用、过期、不一致或未知 | 验证器、执行前检查 |
| 失败交接 | 已取得的来源、错误、相关 `ActionReceipt`、预算 | `HandoffReport` | 程序或 Astra |

表中的目标输出是草案。现有公开方法目前分别返回状态对象、数组、字节或感知结果对象。

## 现有实现

`src/pyrualean/_robot.py` 的 `RobotBase.state`、`image`、`artifact` 按录制步骤读取状态和图像；`show` 请求在代码反馈中附图。
`src/pyrualean/robodojo.py` 的 `RobodojoRobot.camera_meta` 提供录制步骤的相机标定；像素约定是行、列。
这些历史读取能力已存在，不应为建立统一协议而丢失其显式步骤选择能力。

`src/pyrualean/hosts/robodojo_native.py` 的 `Steps.record` 保存图像、状态、任务、标定与截断标记。
其录制索引与原生控制步数分别存为 `step / native_steps`；`observation.json` 保存源 ID、源采集时间、落盘时间、图像来源与对齐标记。无来源协议时明确标记 unverified。

`src/pyrualean/coordination.py` 的 `CoordinationMixin.observe` 先读录制状态，再请求双臂运动状态。
`src/pyrualean/hosts/robodojo_coordination.py` 的 `Controller.observe` 为状态查询保存快照 token，供后续规划检查使用。
因此已有双臂状态观测；它还不是把图像、标定和状态一起冻结的原子视觉快照。

`src/pyrualean/arms.py` 的 `_observe_result`、`_camera_evidence` 已为反馈提供观测编号、状态版本、图像来源与读取期间变化标记。
`display` 图和来源不明的图不会被自动声明为当前相机图；这项区别应保留。
`src/pyrualean/_robot.py` 的 `_action_revision` 在动作尝试开始时递增，它不是传感器帧版本。

`src/pyrualean/hosts/xpolicylab_bridge.py` 的 `Bridge.update_obs` 已处理部分客户端图片落后一帧的情况，保存 `image_state` 并修正对应相机位姿。
`Steps.record` 和新版视觉核验保留该来源关系。旧客户端图片不与当前状态对齐时拒绝严格核验；同一步反复刷新不会给旧图片制造新来源。
`InteractionMixin.snapshot(refresh=True)` 通过只读采集入口获取新来源；默认 `snapshot()` 读取记录。`current_observation_source()` 单独检查实时来源，不把新来源贴到旧 artifact。

native/XPL 的 `locate / back_project / segment / camera_meta` 已接受 `observation_id`，
固定读取该记录的图像、深度、标定和 image_state；历史像素不再静默使用当前标定。
`PerceptionMixin` 校验来源并提供 `perception_is_current / require_current`；推理迟到或后续动作导致的过期可在使用时检查。
RGB 缓存按来源、像素、标定和图像时刻状态区分，快照路径不跨来源复用历史高度。
方法、参与相机、假设与 artifact 引用随结果保存；`views / note / surface` 继续表达估计限制。
详细契约、旧后端限制与测试见[感知快照实施](../perception-snapshots.md)。

## 待补齐契约

### 1. `ObservationSnapshot` 的身份与时间

| 字段组 | 目标约定 |
| --- | --- |
| 身份 | 会话与 episode 身份、采集端观测 ID、各传感器帧 ID；重读不产生新采集 ID |
| 时间 | 分开记录采集、接收、读取时间及所用时钟；源时间不可得时明确未知 |
| 执行关联 | 分开记录原生控制步、录制索引、动作 revision，以及相关动作回执引用 |
| 数据 | 机器人状态、图像引用、标定引用、缺失来源；大文件可以只保留不可变引用 |
| 对齐 | 各来源对应的状态时刻、可测时间偏差、是否一致、图片是否滞后 |
| 有效性 | 过期原因、允许用途、检查依据；不能仅凭一次读取成功判为有效 |

不同 ID 不能单独证明独立观测；同一图像重复读取、裁剪、换问题或重跑模型仍属于同一采集来源。
新的采集也不自动具有统计独立性。连续确认需要按核验对象声明采样间隔、来源变化或其他证据要求。
图像内容相同可以来自真实的新采集，因此不能只靠图像 hash 判断是否重复采样。

### 2. 状态、图像与标定的一致性

采集端应一次返回已对齐的数据包，或显式提供每个来源的时刻与对齐结果。
无法实现原子快照的适配器，应在 `CapabilityManifest` 中声明限制和可保证的最大偏差。
落后图像必须引用其实际对应的 `image_state` 与标定；不能重新贴上当前动作版本后作为当前事实。
读取旧状态不得覆盖当前状态缓存。`RobotBase._readonly` 已将历史读取与当前缓存隔离。

现场可在没有本框架动作调用时变化；有效性检查不能只观察 `_action_revision`。
适配器需说明环境是否在等待模型时推进、哪些传感器可独立刷新，以及外部变化如何被发现。
无法确认现场未变化时，应保留历史上下文并标注当前适用性未知。

### 3. 感知必须绑定输入快照

native/XPL 首批已实现以下身份、图像/标定绑定与当前性检查；其他后端、对象跨帧关联及按时间过期策略仍待补齐。

定位与反投影的目标输入应包含明确快照、相机、分辨率和标定引用；结果原样携带这些引用。
同一结果还需说明坐标系、单位、被识别对象、方法、可见范围和估计限制。
深度测量、多视角估计、桌面平面假设和历史高度先验应能被使用者区分。
`not_found` 表示此输入与方法未找到目标；它不自动证明物体不存在。
几何估计不足时不能静默生成可执行坐标，程序必须检查结果是否适用于下一动作。
缓存的命中条件应包括来源、标定和对象身份；历史先验不能改写为新测量。

### 4. 能力、副作用与预算

`CapabilityManifest` 应区分历史读取、新观测、推理、规划、执行和停止，并声明资源成本与物理副作用。
现有物理只读原语可以写缓存和审计记录；“物理只读”不意味着进程内存绝不变化。
需要运动才能清除遮挡时，应报告所需主动观测条件，由程序或 Astra 选择动作。
`BudgetSnapshot` 应分别表达剩余采集、推理和时间预算；耗尽观测预算不能通过微小动作绕过。
独立核验如何消费快照、写入 `EvidenceRecord`，见[验证与证据](verification-evidence.md)。

## 失败交接

| 情况 | 本模块输出与停止范围 | 下一责任方 |
| --- | --- | --- |
| 来源缺失或采集超时 | 保留已取得的数据；标记缺失来源，不能宣称完整快照 | 程序按预算重采；无规则可处理则 Astra |
| 图像与状态不一致 | 返回各自来源及不一致原因；禁止依赖精确几何的后续使用 | 观测适配器重新对齐或 Astra 调整策略 |
| 遮挡、身份或几何不确定 | 返回未知与方法限制；不自动触发机器人运动 | 程序或 Astra 决定是否主动观测 |
| 现场在读取期间变化 | 旧数据保留为历史；当前有效性不成立 | 验证器拒绝建立当前事实，程序重新观察 |
| 动作结果未知 | 附相关 `ActionReceipt`；不把一次观测直接等同于停止确认 | 执行系统核对回执，Astra 再决定继续方式 |
| 预算不足 | 返回 `BudgetSnapshot` 和已取得的证据引用 | 运行时生成 `HandoffReport`，交 Astra |

`HandoffReport` 应携带原始来源、错误类别、是否发生主动观测动作、当前已知状态和剩余预算。
交接不意味着回滚、重放动作或已确认环境静止。

## 验收场景

以下是未来需要验证的场景；本文没有运行这些验收。

1. 重读同一录制图、裁剪该图、重新推理，采集身份不变且不增加独立确认次数。
2. 无动作时可以取得适配器支持的新观测；不支持刷新时明确报告限制。
3. 历史图像的像素只能使用其绑定状态与标定解释，不能静默改用当前观测。
4. 图片落后一帧时，保存、反馈、感知和验证全链路都保留真实对应关系。
5. 原生控制步、录制索引、动作 revision 不同，仍能精确定位相关图像和动作。
6. 多相机读取过程中发生现场变化，快照不得被标为一致且新鲜。
7. 只读定位、反投影、验证不发出原生动作；改变视角必须进入动作回执链。
8. 采集时间不可得、几何估计不足或预算不足时，失败交接保留未知并给出可追溯原因。
