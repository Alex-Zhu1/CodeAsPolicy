# PyRUA-Lean 开发 RSI

把开发经验变成下一轮工作的输入：**查已有证据 → 提出可检验假设 → 最小修复 →
匹配范围的验证 → 保留结果和适用条件 → 更新经验。**
目标是减少重复排查，并让“这次验证了什么”可追溯。

本 skill 供开发代理使用。仓库中的 `skills/` 文件不会自动注入机器人评测策略；
也不会改动 `integrations/xpolicylab/PyRUA_RSI/programs/`。
未安装到技能发现目录时，可直接要求代理读取本文件执行流程。

## 先复用已有证据

- 从当前请求确定目标：修复接口行为、解释失败、改善任务结果，或仅整理经验。
  单纯整理记录时，读取已有产物即可；不因此启动模型或仿真。
- 检查 `git status --short` 和目标 diff。工作区经常含未提交的新模块；
  `git diff` 单独看不到 untracked 文件，不能据此认定改动完整。
- 按问题查阅 [经验记录](references/lessons.md)，找到原始报告和可复现输入。
  路径缺失时保留“历史记录”标签，不把摘要说成本轮复验。
- 查 runs 时指定任务目录或浅层文件，避免递归扫入 `frozen/`、`benchmark/`、
  `bench/`、虚拟环境和 `codex-home/`。这些目录有大量重复源码、资产或凭据。

## 明确本轮要证明什么

用一句话写出：观察到的失败、怀疑的原因、拟改变的变量、能推翻假设的检查。
先选最近的可比较基线；在线模型路径变化与控制器变化需要分开解释。

| 想证明的结论 | 合适的证据 |
| --- | --- |
| API、预算、幂等、unknown/partial 语义正确 | 针对性测试，包含相关失败路径 |
| 真实客户端能启动并执行该协议 | 小规模 wiring / simulator 检查 |
| 控制器修复了特定轨迹问题 | 同一公开指令或动作序列的固定对照 |
| 当前版本完成某任务 | 当前配置的原生结果，附动作与图像记录 |
| 普遍改善成功率或速度 | 固定版本、同配置、多样本的预先选定评估 |

接口修改先运行相关测试；扩大到公共执行路径时，再覆盖调用方与代表任务。
已经通过且没有新改动或疑点时，结束验证。不要为小文档改动跑全量仿真。

## 执行前固定版本与配置

需要测试命令或启动实验时读 [操作手册](references/commands.md)。优先复用已能工作的
解释器和依赖，先确认 `sys.executable`、模块导入位置与必要资源。

耗时实验使用新的 `runs/<目的>-<时间>/`，记录源码快照及 SHA-256、基点与 dirty 状态、
实际 argv、Python 与客户端来源、任务/layout/eval seed、模型/runtime/reasoning、
观测/反馈模式、监督与恢复开关，以及原生步数、turns、墙钟预算。
冻结范围包括新增源码、打包知识和实际使用的 adapter；测试记录对应测试时的版本。
运行中修改工作区，不能把新版本标记为已被旧快照验证。

沿用用户指定的实验条件。历史使用过的 GPU、端口、1000 步或监控开关只是该轮配置，
不是通用默认值。需要私有 benchmark 改动时记录精确差异，尤其不能混淆预算实验与标准评测。

## 从证据定位故障

按症状读取最小相关记录：

1. **启动失败**：检查 `episode.log`、`host.log`、`robodojo_eval_client.log` 和实际环境。
   资源修好后在新目录重试，保留原 attempt；已执行动作的中断实验也记录实际消耗。
2. **动作异常**：连接 `calls.jsonl`、`tool_turns.json` 与 execution journal 的
   request/operation/action ID，确认实际推进、partial、unknown 和停止原因。
   回执未明时先对账；恢复已有操作不能通过重跑整段 cell 来猜测现场。
3. **感知或抓取疑问**：核对原始图像、observation ID、基线时刻及证据维度。
   `holding`、二维一致性、三维跟随与任务成功是不同结论。
4. **分数与视觉/模型结论冲突**：先找原生结果。必要时在独立副本做事后只读判定诊断，
   保持评分规则与物理不变，核对回放是否匹配；诊断信息不回灌当前评测策略。
5. **耗时异常**：区分启动、模型/工具等待、动作和收尾。用现有 latency 分析器，
   不把不同路径的单次墙钟差异解释成控制器提速。

同一故障再次发生时，先确认上次修复是否实际加载，再决定下一项诊断。
重试应有变化依据和明确预算；既定验证完成后停止，不开展无边界循环。

## 收尾并更新经验

保留四类结论：测试结果、执行/账本状态、模型 finish、原生 success/score。
`status=completed` 只表示运行结束，模型自报成功也不替代原生判定。
原生聚合分和单 episode 细节分可能采用不同量纲，记录原始字段，不猜换算。

可先用只读助手收集结果：

```bash
python skills/pyrualean-dev-rsi/scripts/inspect_run.py runs/<实验目录> --verify-source
```

助手不启动机器人或模型，不写回归档；它不替代视频、账本或评分器审查。
报告缺失、多个原生结果或哈希不符时先解决对应疑点，再给结论。

每次得到新的可复用结论，按 [经验条目格式](references/lessons.md#更新格式)
更新对应条目：触发症状、有效做法、命令/产物、适用版本、验证层级和反例。
优先修订旧条目，合并重复经验。只有推测时标为“待验证”，不升级成强制流程。
遇到反证时缩小适用范围或标为被替代，保留原证据。

交付应说明改了什么、验证对应哪个版本、结果与限制、可复用的新经验在哪里。
`runs/*` 默认被 Git 忽略；将简短结论和证据索引留在受版本管理的经验记录中，
原始视频/日志留在实验目录。保存文件不代表已安装、已自动加载或已验证所有任务。
